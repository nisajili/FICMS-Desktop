# API

The FICMS backend is a NestJS service exposing a **versioned REST API** under
`/api/v1`. Interactive Swagger UI is available at `/docs`, and the OpenAPI 3
specification at `/docs-json`. A committed copy of the spec ships in
[`docs/openapi.json`](openapi.json) (147 paths, 175 operations, bearer auth).

## Authentication

- `POST /api/v1/auth/login` → `{ accessToken, refreshToken, user, mustChangePassword }`.
- Send the access token as `Authorization: Bearer <token>`.
- `GET /api/v1/auth/me` returns the current user and their effective permissions.
- `POST /api/v1/auth/logout` invalidates the session.
- TOTP two-factor authentication is supported when enabled on the account.

## Public endpoints

- `GET /api/v1/health` and `GET /api/v1/health/ready`
- `GET /api/v1/settings/branding` — clinic name, locale, currency, colors,
  languages (used by the login screen; no authentication required).

## Module overview

| Prefix | Module | Highlights |
|---|---|---|
| `/auth` | auth | login/logout/me, 2FA |
| `/users`, `/roles` | users | staff accounts, roles |
| `/patients` | patients | registration (encrypted PII), demographics, MRN |
| `/clinical` | clinical (EMR) | consultations, notes, prescriptions, investigations |
| `/cycles` | cycles | ART/IVF/ICSI/IUI cycles, timeline, follicles, hormones, oocytes, fertilization, embryos, PGT |
| `/laboratory` | laboratory | samples, analyses, results, QC, accessioning, verify/release |
| `/cryobank` | cryobank | facility→room→tank→canister→cane→goblet→rack→position hierarchy, items, transfers, witness |
| `/finance` | finance | invoices, payments (idempotent), credit notes, shifts, revenue |
| `/inventory` | inventory | stock, movements, adjustments, FEFO issue, suppliers, purchase orders |
| `/settings` | settings | clinic, branches, departments, services, tests, medications, templates, branding |
| `/reports` | reports | CSV/XLSX/PDF exports |
| `/documents` | documents | attachments (S3 or local storage) |
| `/donors` | donors | donor registration (encrypted identity), donations |
| `/counseling` | counseling | counseling sessions (restricted, encrypted notes) |
| `/hr` | hr | staff profiles, attendance, leave |
| `/imaging` | imaging | ultrasound studies (encrypted findings, verification) |
| `/nursing` | nursing | vitals and nursing notes |
| `/sync` | sync | offline sync push/conflicts/status |
| `/backup` | backup | backup + integrity check |
| `/health` | health | liveness/readiness |

## Example

```bash
# login
curl -sS -X POST http://127.0.0.1:4123/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"ChangeMe123!"}'

# list patients (first page of 20)
curl -sS http://127.0.0.1:4123/api/v1/patients \
  -H "Authorization: Bearer $TOKEN"

# public branding
curl -sS http://127.0.0.1:4123/api/v1/settings/branding
```

## Versioning policy

- The current version is `v1` (`/api/v1`).
- Breaking changes require a new major prefix; additive changes stay within the
  same prefix.
- DTOs are validated with zod schemas; invalid payloads return `400` with
  structured errors.

## Note on the OpenAPI spec

The spec lists every route with method, parameters, and security requirements.
DTO schemas are validated by zod at runtime; the Swagger document reflects
routes and auth but (in the current build) does not auto-generate request-body
schemas for all endpoints. The committed `docs/openapi.json` is the route-level
source of truth and is regenerated by running the API and fetching `/docs-json`.
